# PRD — 기사 페이지 (활동 지역 설정 · 화물 추천 · 수락)

- 프로젝트: 집나간 벌꿀오소리 (카카오모빌리티 물류 해커톤)
- 기준 자료: `docs/집나간 벌꿀오소리.html` (Hi-fi mockup, SCREEN 2 · 기사 페이지)
- 연관 문서: `docs/superpowers/specs/cargo-matching-api-design.md`, `docs/superpowers/plans/cargo-matching-api.md`, `docs/superpowers/specs/shipper-page-prd.md`(화주 페이지 PRD, 같은 표기 규칙 사용)

> 표기 규칙: 🤖 **[AI 필요]** 로 표시된 기능은 Claude API 호출 없이는 동작할 수 없는 핵심 AI 구간이다. 나머지는 규칙 기반 로직이나 단순 CRUD로 구현한다. 이번 문서에서도 AI 지점은 **실제로 구현하지 않고 TODO로만 남겨두는 것**을 전제로 요구사항을 정리한다 (화주 페이지와 동일한 방침).

## 1. 배경 및 문제 정의

기사는 하루에도 여러 건의 화물 제안을 받지만, 그중 자기 차량·활동 지역·수락 가능한 운임에 맞는 것만 빠르게 골라야 한다. 조건에 안 맞는 화물까지 다 훑어보는 건 시간 낭비고, 운임이 시세보다 낮은 화물을 모르고 수락하면 손해다.

기사 페이지의 핵심 가치:
1. **활동 지역을 한 번 설정해두면, 그 조건에 맞는 화물만 걸러서 보여준다.**
2. **점수순으로 정렬해서 "이 중 뭘 먼저 볼지"를 대신 판단해준다.**
3. **운임이 시세보다 낮은 화물은 수락 전에 바로 알려준다.**

## 2. 목표

- 기사가 활동 지역을 설정하면, 그 조건에 맞지 않는 화물은 애초에 목록에 안 보이게 한다 (필터링).
- 남은 화물은 매칭 점수순으로 정렬해서, 맨 위 1건은 "최적 매칭"으로 강조한다.
- 시세보다 눈에 띄게 낮은 운임의 화물은 수락 전에 경고 배지로 알린다.
- 화물 수락은 한 명만 성공해야 한다 (동시 수락 방지).

## 3. 사용자 흐름 (mockup 기준)

```
[활동 지역 설정] ──저장──> [01 추천 화물 목록 (점수순, 배지 포함)] ──수락──> (화물이 목록에서 사라짐)
                                  │                                      │
                                  ├──새로고침── 목록 재조회                │
                                  └──숨기기── 이 화물을 목록에서만 감춤 (서버 저장 안 함)
```

- 활동 지역은 출발지(시도+시군구)와 도착지(시도+시군구)를 각각 설정한다. **시군구 자리에 "전체"를 선택하면 그 시도 전체가 대상**이다 (mockup의 도착지 예시: "서울특별시 / 전체").
- 목록은 진입 시 자동 조회되고, 새로고침 버튼으로 다시 불러온다.
- "숨기기"는 목록에서만 안 보이게 하는 화면 단 동작이다 — 서버에 저장하지 않는다 (§6 참고).

## 4. 기능 요구사항

### F-1. 활동 지역 설정 조회/저장

- 진입 시 기사의 현재 활동 지역(출발지 목록, 도착지 목록)을 불러와 드롭다운에 채운다.
- 출발지·도착지 각각 시도/시군구를 선택한다. 시군구를 "전체"로 두면 그 시도 전체가 조건이 된다.
- **복수 선택이 전제다** — mockup 화면 자체는 단일 드롭다운 쌍만 보여주지만, 설계 문서상 기사는 출발지·도착지 각각 여러 구간을 등록할 수 있다("경기 수원시 / 경기 용인시 / 서울 전체"처럼). 이 화면은 그중 하나를 추가/수정하는 단위 상호작용으로 보고, 목록에 추가된 지역들을 칩(chip) 형태로 관리하는 UI가 필요하다 — mockup에는 이 목록 관리 UI가 없다 (§7).
- 저장하면 전체 교체 방식으로 반영된다 (보낸 목록이 곧 새 활동 지역 전체).
- **AI 관여 없음.**

### F-2. 추천 화물 목록 (핵심 기능)

- F-1에서 설정한 활동 지역을 기준으로, 조건에 맞는 `REQUESTED` 상태 화물만 걸러 점수순으로 내려준다.
- 각 화물 카드에 표시되는 정보: 구간(출발→도착), 상차/하차 일시, 차종·중량·적재함·화물종류(예: "카고 · 22t · 원종차 · 냉장"), 운임, 운임 적정성 배지.
- **최상위 1건에는 "✦ 최적 매칭" 라벨을 붙인다.**
- 목록이 비면 "조건에 맞는 화물이 없습니다" 안내가 필요하다 (mockup에는 없는 상태 — §7).
- **매칭 스코어링은 AI가 아니다.** `cargo-matching-api-design.md`에 정의된 룰 기반 가중합으로 계산한다:

  | 항목 | 배점 |
  |---|---|
  | 구간일치 (출발+도착) | 최대 40 |
  | 차량적합 (`capacityTon >= weightTon`, 미달 시 목록에서 제외) | 25 |
  | 시간여유 (상차까지 남은 시간) | 최대 20 |
  | 운임매력 (`fare >= minAcceptFare`) | 최대 15 |

  외부 API 호출 없이 응답해야 하므로 목록 API의 지연 시간을 짧게 유지할 수 있고, "왜 이 화물이 위에 있는지"를 그대로 설명할 수 있다는 게 룰 기반을 택한 이유다 (design 문서 §1 참고). **AI 관여 없음.**
- **새로고침 버튼**은 별도 기능이 아니라 이 목록 조회를 다시 호출하는 것이다.

### F-3. 운임 적정성 배지 🤖 **[AI 필요 — 간접]**

- 각 카드에 운임 적정성 배지가 붙는다:
  - `적정 운임` — 정상 배지
  - `운임 N% 낮음` — 구간 평균 대비 낮을 때, 카드 안에 "이 구간의 평균 운임은 OOO원이에요" 배너까지 함께 노출
- **`BEST_MATCH`(최적 매칭)와 `BELOW_AVERAGE`(운임 낮음)가 동시에 해당하면 `BELOW_AVERAGE`가 우선한다** — 기사에게 불리한 정보를 먼저 보여준다는 게 설계 의도다.
- **AI가 필요한 이유**: 배지 판정과 "구간 평균 운임" 수치 자체가 화주 페이지(F-3 운임 코칭)와 **같은 시세 추정 캐시(`FareQuoteService`)**를 재사용한다. 시세 자체는 Claude가 최초 1회 추정해 DB에 캐싱해두는 값이라, 이 캐시가 비어 있으면(=아직 그 구간을 아무도 조회한 적 없으면) 배지를 계산할 데이터가 없다.
- **실패/미구현 시 폴백**: 시세 조회가 안 되면(AI 미연동, cache miss, API 장애 등) 배지 없이 화물 카드 자체는 정상 노출해야 한다 — 목록 전체가 막히면 안 된다. 이 폴백은 화주 페이지 CargoService에 이미 구현된 `quoteOrNull` 패턴을 그대로 재사용할 수 있다.

### F-4. 화물 수락

- "수락" 버튼을 누르면 해당 화물을 배차 확정한다.
- **동시성 처리가 핵심이다**: 두 기사가 같은 화물을 동시에 수락할 수 있으므로, 조건부 UPDATE(`status가 REQUESTED일 때만 MATCHED로`)의 영향 행 수로 승패를 가른다. 늦은 쪽은 `CARGO_ALREADY_MATCHED`(409)를 받는다.
- 적재량이 부족한 기사가 수락을 시도하면 `VEHICLE_NOT_SUITABLE`(400).
- 수락에 성공하면 그 화물은 다음 목록 조회부터 빠진다(상태가 더 이상 `REQUESTED`가 아니므로).
- **AI 관여 없음.**

### F-5. 숨기기 (서버 미저장)

- "숨기기"를 누르면 그 화물이 현재 세션의 목록에서만 사라진다.
- **서버에 저장하지 않는다.** 새로고침하거나 다시 접속하면 숨겼던 화물도 다시 보인다 — 클라이언트 로컬 상태로만 관리한다 (design 문서에서 이미 범위 밖으로 명시된 결정).
- 세션 간 유지가 필요해지면 `HiddenLoad(driverId, cargoId)` 테이블과 `POST /loads/{id}/hide`가 필요하다는 TODO만 남겨두고, 이번 범위에서는 만들지 않는다.

## 5. AI 필요 기능 요약

| 기능 | AI 사용처 | AI 없이 대체 불가능한 이유 | 실패 시 폴백 |
|---|---|---|---|
| 🤖 F-3 운임 적정성 배지 / 구간 평균 운임 안내 | 화주 페이지와 공유하는 시세 추정 캐시(`FareQuoteService`)에서 평균 운임을 읽어옴 | 실거래 데이터가 없어 시세 자체를 AI가 최초 추정해야 함 (화주 페이지 F-3와 동일 근본 원인) | 시세 조회 실패 시 배지 없이 화물 카드는 그대로 노출 — 목록 전체를 막지 않는다 |

**AI가 아닌데 가장 AI처럼 보이는 부분** (오해 방지용): **F-2 매칭 점수 계산과 화물 정렬 자체는 100% 규칙 기반**이다. "이 기사에게 이 화물이 왜 뜨는지"는 표에 정리된 가중치 공식으로 전부 설명 가능하며 Claude 호출이 전혀 없다. 발표 때 "AI가 매칭해준다"고 뭉뚱그려 말하지 않도록 주의 — AI는 오직 시세 추정(운임 배지)에만 관여한다.

## 6. 화면 밖 범위 (Out of scope)

- 기사 회원가입·등록 (seed 데이터로 이미 가입돼 있다고 가정)
- 숨기기 서버 저장 (TODO로만 남김, §4 F-5 참고)
- 실시간 위치 추적, 운행 중 상태
- 화물 목록의 실시간 푸시 (새로고침 버튼으로 대체)
- 기사의 평점·완료율·최근 운행 이력 등록/수정 화면 (seed 값 전제)

## 7. Mockup에 없지만 필요한 상태 (구현 시 보강 필요)

- **활동 지역 복수 선택 UI**: mockup은 드롭다운 1쌍(출발지 시도/시군구, 도착지 시도/시군구)만 보여주지만, 실제로는 여러 구간을 추가/삭제할 수 있는 칩 목록 UI가 필요하다.
- **빈 목록 상태**: 조건에 맞는 화물이 하나도 없을 때의 안내 화면이 mockup에 없다.
- **로딩 상태**: 새로고침 버튼을 눌렀을 때의 로딩 표시가 없다.
- **수락 성공/실패 피드백**: "수락" 버튼을 눌렀을 때 성공 토스트, 또는 `CARGO_ALREADY_MATCHED`(다른 기사가 먼저 가져감)·`VEHICLE_NOT_SUITABLE` 에러 상황의 화면 처리가 정의돼 있지 않다.

## 8. 오픈 이슈

1. **활동 지역이 비어 있을 때 목록 API는 어떻게 응답하나** — 기사가 아직 활동 지역을 한 번도 설정하지 않았다면 전체 화물을 보여줄지, 빈 목록을 보여줄지 정책이 필요하다.
2. **"숨기기" 버튼 인접 화면 갱신** — 숨긴 화물이 세션 내에서 실제로 리스트에서 사라지는지, 아니면 그냥 흐리게 처리되는지 mockup 스타일만으로는 애매하다(디자인 쪽 확인 필요).
3. **F-3 배지 캐시 워밍업 전략** — 화주가 아직 등록하지 않은 신규 구간의 화물이 기사 목록에 뜰 경우, 그 구간 시세 캐시가 없어 배지 없이 노출된다. 데모 시나리오에서 이게 어색해 보이지 않으려면 자주 나오는 구간은 사전에 캐시를 채워두는 seed 작업이 필요할 수 있다.
